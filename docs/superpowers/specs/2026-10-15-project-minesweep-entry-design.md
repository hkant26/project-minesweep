# 项目排雷通用入口(project-minesweep)设计

- 日期:2026-10-15
- 状态:已实施(2026-10-15 全量落地;pre-mortem 后经文末修订记录解冻增强)
- 范围:`claude-review-skills` repo 重定位为「项目排雷」——新增通用入口技能,三引擎零改动,repo 改名,README 重写,本地同装

## 背景与目标

repo 现为三个场景化评审技能(hypothesis-challenge / red-team / pre-mortem),触发词各自指向明确场景。「帮我排雷」「这项目靠谱吗」这类**不知道该用哪个、或根本不知道有三个技能**的模糊请求,现在没有任何技能接得住。

目标:补一个通用入口 `project-minesweep`,把模糊请求统一收口,判明项目阶段后路由到对口引擎。入口**不生产分析,只判阶段+路由**。

## 已对齐的决策

1. 结构 = **B:通用入口 + 三引擎**(三合一被否:大文件、丢触发调优;只改包装被否:触发面没变宽)
2. 射程外 = **甲:诚实边界**(不发明第四引擎;进行中项目明说不在射程,给最近可用形态)
3. 命名落地**全收**:入口名 `project-minesweep`;repo 同步改名;本地 `~/.claude/skills/` 同装

## 设计

### 1. 入口技能 `project-minesweep`(唯一新增文件,~100 行)

**定位**:排雷总入口。拿到任意项目材料 → 判阶段 → 路由 → 退出。自己不输出分析报告,只允许一句路由说明。

**触发分工**(description 承载,防与引擎撞车):

| 请求形态 | 归属 |
|---|---|
| 「排雷 / 项目排雷 / 有什么雷 / 雷区扫一遍」 | 入口(新占位) |
| 「这项目/方向靠谱吗」「帮我挑挑毛病」「把把关」,阶段不明 | 入口(判完路由) |
| 明说 红队/red team/答辩预演/扮演对手 | red-team(入口让位) |
| 明说 事前验尸/premortem/会怎么死/上线前评审 | pre-mortem(入口让位) |
| 明说 假设地图/挖隐含假设/前提靠不靠谱 | hypothesis-challenge(入口让位) |
| 代码审查 / 渗透测试 / 纯调研头脑风暴 | 入口拒绝(不适用) |

入口 description 末尾写 Not-for 子句,把引擎显式关键词全部让出去——仲裁靠 description 边界子句,与三引擎互相让位的既有机制同构。

**阶段判定**(入口的唯一智能,三路信号):

1. 用户原话:「该不该做/值不值得」→ 未定稿;「要过会/融资/答辩/客户选型」→ 闯关;「马上开干/上线/迁移」→ 执行前
2. 文本形态:几段讨论/一页提纲/无具体数字排期 → 未定稿;有完整数字/排期/分工的方案书 → 定稿
3. 外部关卡存在性:定稿 + 有评审席 → red-team;定稿 + 直接执行 → pre-mortem

三信号冲突或全弱时,**一次问齐三选一**(带推断默认值,复用引擎「背景锁定」问法:回复「确认」即按默认),不开放式填空、不空转自答。

**路由规则**:

- 单一阶段 → invoke 对应引擎(Skill 工具,引擎名逐字),由引擎完成背景锁定与全量输出
- 双需求(闯关 + 怕执行死)→ 按引擎既有约定:先 red-team 找伤口、后 pre-mortem 排死法,两轮独立输出,不合并
- 完全没有方向文本 → 不路由(见射程外)

**射程外话术(甲)**:进行中项目 / 零文本 / 纯调研——一句话边界:「三引擎都吃方案文本(想法→定稿→计划),进行中的项目不在射程内」+ 最近可用形态(如:把现状与下一步计划写成文本,再跑 pre-mortem)。不做任何扫描兜底。

**输出边界**:对话内路由说明仅一两句;不写文件;不总结引擎产出。

## 验收口径

手动触发冒烟,6-8 条短语:

1. 「帮我排雷」/「这项目靠谱吗」→ 入口接住并路由
2. 「红队这份 BP」/「这方案会怎么死」/「挖一下隐含假设」→ 对应引擎直接接,入口不抢
3. 「帮我给这个跑了半年的系统排排雷」→ 射程外话术
4. 阶段模糊材料(如一段半页提纲 + 一句「要去找投资人」)→ 入口问齐三选一而非瞎猜

skill-creator eval 本机有坑(延迟工具/并发 uid/recall=0 假象,备忘),不在本次验收内承诺。
